# Ефір Yantarne.FM у Telegram-каналі: тестовий запуск

Сервер (`server/`) цілодобово ретранслює ефір у трансляцію Telegram-каналу.
Для тесту використовуємо канал **@yantarnetest**.

## Що змінено в коді

| Файл | Що зроблено |
|---|---|
| `server/src/services/telegramStream.js` | **новий**: ретрансляція ефіру з автоматичним перепідключенням |
| `server/assets/telegram-cover.jpg` | **новий**: картинка трансляції 1280×720 (логотип і частоти) |
| `server/main.js` | після старту сервера запускається ретрансляція (+2 рядки) |
| `server/src/routes/telegramRoutes.js` | новий маршрут `GET /telegram/stream-status`: стан трансляції |
| `server/package.json` | додано залежність `ffmpeg-static` |

Поки змінна `TG_STREAM_ENABLED` не дорівнює `true`, сервер працює як раніше.

## Крок 1. Отримати адресу й ключ у Telegram (канал @yantarnetest)

Потрібно бути власником або адміністратором каналу з правом керувати трансляціями.

1. Відкрийте канал → натисніть на назву каналу → **Трансляція** (Live stream).
2. Оберіть **«Транслювати через…»** (Stream with…).
3. Telegram покаже **URL сервера** (на кшталт `rtmps://dc4-1.rtmp.t.me/s/`) і **ключ трансляції**.
4. Натисніть **«Почати трансляцію»**. Канал чекатиме на сигнал від сервера.

⚠️ Ключ трансляції — це пароль. Не надсилайте його в чати й не додавайте в код.

## Крок 2. Налаштування на Render

Render → ваш сервіс з сервером → **Environment** → додайте:

| Змінна | Значення |
|---|---|
| `TG_STREAM_ENABLED` | `true` |
| `TG_RTMP_URL` | URL сервера з Telegram, напр. `rtmps://dc4-1.rtmp.t.me/s/` |
| `TG_STREAM_KEY` | ключ трансляції з Telegram |
| `STREAM_SOURCE_URL` | (необов'язково) за замовчуванням `https://complex.in.ua/yantarne` |
| `TG_STREAM_DEBUG` | (необов'язково) `true` — докладні логи для пошуку проблем |

## Крок 3. Завантажити код і перезапустити

1. Додайте змінені файли в репозиторій, з якого Render розгортає сервер, і зробіть push.
2. Render сам встановить `ffmpeg-static` і перезапустить сервер.
3. У логах Render має з'явитися рядок `📡 Telegram-трансляція: запуск (...)`.
4. Приблизно за 10–20 секунд у каналі @yantarnetest піде звук.

## Як перевірити

- Відкрийте `https://<адреса-сервера>/telegram/stream-status`:
  - `"status": "live"` — ефір іде;
  - `"restarting"` — перепідключається (дивіться `lastError`);
  - `"error"` — не задано змінні або немає картинки.
- Ключ у статусі й логах ніколи не показується.

## Як зупинити

Поставте `TG_STREAM_ENABLED=false` (або видаліть змінну) і перезапустіть сервіс.

## Корисно знати

- **Трафік.** Приблизно 180 кбіт/с, тобто близько **55–60 ГБ вихідного трафіку на місяць**. Перевірте, скільки входить у ваш тариф Render.
- **Один екземпляр.** Сервіс має працювати в одному екземплярі (instance). Якщо їх буде два, обидва почнуть транслювати в той самий канал.
- **Оновлення коду.** Під час кожного розгортання сервера ефір у Telegram переривається приблизно на хвилину, поки сервіс перезапускається.
- **Як влаштовано.** Мережею займається Node.js, а ffmpeg лише перекодовує звук і картинку. Так зроблено, бо статична збірка ffmpeg з npm не вміє знаходити сервери за доменним іменем.
- **Перевірено локально.** Тестовий «Telegram-сервер» (RTMPS) отримував відео 1280×720 з 2 кадрами на секунду (H.264) і звук AAC стерео. На справжньому Telegram ще не перевірялося.
- **Інший канал.** Щоб перейти на основний канал @yantarnefm24, змініть `TG_RTMP_URL` і `TG_STREAM_KEY` на значення з того каналу.
